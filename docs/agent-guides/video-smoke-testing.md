# Video Smoke Testing Guide

This guide verifies the complete video flow for local development:

1. Kickoff API creates a video job
2. Segments are generated by `video-worker`
3. Final MP4 is stitched to local disk
4. Metadata/API return `ready` and streamable `video/mp4`

## Preconditions

- Docker services available (`supabase`, `synthesis-agent`, `video-worker`)
- Local `.env` present
- Python venv available at `.venv`

## One-Time Setup

Apply migration for video tables if needed:

```bash
docker compose exec -T supabase psql -U postgres -d studysync < db/migrations/004_add_video_artifacts.sql
```

## Start Services

```bash
docker compose up -d --build supabase redis synthesis-agent video-worker
```

Run gateway in a separate terminal:

```bash
source .venv/bin/activate
set -a && source .env && set +a
cd gateway
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Health check:

```bash
curl -sS http://127.0.0.1:8000/health
```

## Run Smoke Test

```bash
source .venv/bin/activate
set -a && source .env && set +a
python -u scripts/smoke_video_kickoff.py --user-id video_smoke_$(date +%s)
```

Expected output:

- `PASS: video generation kickoff and metadata flow verified.`
- A `video_id` and `artifact_id` printed in output

## Confirm Completion

Use IDs from smoke output:

```bash
VIDEO_ID="<video_id>"
ARTIFACT_ID="<artifact_id>"

docker compose exec -T supabase psql -U postgres -d studysync -c \
  "select id,artifact_id,status,file_size_bytes,video_path from video_artifacts where id='${VIDEO_ID}';"

docker compose exec -T supabase psql -U postgres -d studysync -c \
  "select count(*) as ready_segments from video_segments where video_artifact_id='${VIDEO_ID}' and status='ready';"
```

When complete:

- `video_artifacts.status = 'ready'`
- all segments `ready`

## Verify Local File + Stream

```bash
ls -lh storage/video/${ARTIFACT_ID}_complete.mp4

curl -sS -o /tmp/video_smoke.mp4 \
  -w 'status=%{http_code} bytes=%{size_download} type=%{content_type}\n' \
  http://127.0.0.1:8000/api/v1/video/${ARTIFACT_ID}_complete.mp4
```

Expected:

- local file exists in `storage/video/`
- stream returns `status=200` and `type=video/mp4`

## Timing Expectations

- Placeholder mode (`VIDEO_PROVIDER=placeholder`): usually ~10-20 seconds
- Real Veo mode: usually minutes (depends on API and segment count)

## Why Demo Videos Are Colorful, Not Real Content

For smoke tests, `video-worker` uses deterministic placeholder segments (rainbow/ice-cream themed overlays) so you can visually confirm the pipeline is working without waiting on real video generation.
